# СтройКонтроль

Мониторинг строительной площадки по снимкам камер: детекция техники (YOLO), определение фактического этапа работ,
сверка с графиком, выявление отклонений, таймлайн со статусами, прогноз окончания и отчёт с рекомендациями.

Хакатон Департамента градостроительной политики г. Москвы.

**Методология подбора техники и определения этапа работ — [METHODOLOGY.md](METHODOLOGY.md)** (для судейской коллегии):
пошаговый алгоритм, нормативная база (СП, ГОСТ, СНиП), связь «тип объекта ↔ этап ↔ техника» в БД, расчёты количества техники.

## Быстрый запуск (Docker)

```bash
docker compose up --build
```

- Интерфейс: http://localhost:8080
- API и Swagger: http://localhost:8000/docs

Первая сборка скачивает PyTorch (CPU), YOLO-World и CLIP — около 3 ГБ, 10–15 минут. После сборки сервис работает без интернета.

Быстрая сборка без нейросети (детектор-заглушка, удобно проверить интерфейс):

```bash
docker compose build --build-arg WITH_ML=0 backend && DETECTOR=mock docker compose up
```

## Запуск без Docker

```bash

python -m venv .venv && . .venv/bin/activate

```

## Сценарий работы

1. Регистрация или вход.
2. Создание стройки: название, адрес, сроки.
3. Добавление объекта и выбор типа (9 типов справочника). План работ формируется автоматически.
4. Проверка плана: включение и отключение работ, правка сроков, пересчёт по типовому графику.
5. Снимки: пакетная загрузка с назначением времени (старт + интервал) и привязкой к камере. Камера — метка точки
   съёмки (название, зона площадки, объект): по соседним кадрам одной камеры определяется, работает техника или стоит.
6. Детекция техники на каждом снимке; определение «работает / стоит» по соседним кадрам одной камеры.
7. Автоопределение фактического этапа по набору техники с учётом графика.
8. Вердикт «что есть и чего нет» по методике, отклонения с зоной и снимками-доказательствами.
9. Таймлайн этапов с цветом статуса, готовность, SPI, прогноз окончания, риск задержки.
10. Отчёт по стройке (HTML, печать в PDF) и журнал отклонений.
11. Карта строек Москвы на главной странице (под списком): метки по адресам с цветом статуса, карточка стройки
    с готовностью и переходом в неё. Нераспознанный адрес можно поставить на карту вручную.
12. Помощник по документации (бета, пункт «Помощник β» в меню): чат с потоковым ответом, быстрые вопросы
    («текущий этап», «почему простой», «кому звонить»), источники ответа, добавление своих документов.
13. Этап у каждого снимка: сразу после загрузки по видам и количеству техники определяется примерный этап
    (или снимки загружаются сразу на выбранный этап). Факт этапа виден на диаграмме Ганта «План работ» (план —
    полупрозрачная плашка, факт — яркая по датам снимков, отметки камер, линия «Сегодня», дата под курсором) и в
    таблице «Все работы» (главные этапы, подпункты раскрываются; «Загрузить» / «Посмотреть фото» с мини-окном
    дозагрузки). У каждого этапа своя страница со всеми снимками, их анализом против норм техники и расчётом.
14. Экран «Фото и техника» объединяет бывшие «Мониторинг техники» и «Фото и отклонения»: вердикт по последнему
    снимку, блоки «Снимки объекта» и «Камеры».

## Карта строек

Точка берётся из координат стройки; если их нет, бэкенд геокодирует адрес (`POST /api/projects/{id}/geocode`):
геокодер Яндекса (при `YANDEX_GEOCODER_KEY`) → Nominatim/OpenStreetMap → встроенный справочник округов и магистралей
Москвы (работает без интернета, точка помечается «приблизительно»). Ручная точка — `PATCH /api/projects/{id}` с `lat`/`lon`.
Подложка — тайлы OpenStreetMap (Leaflet); свой тайл-сервер: `VITE_MAP_TILES`, `VITE_MAP_ATTRIBUTION` при сборке фронтенда.

## Помощник (бета)

Макет RAG без языковой модели и без скачивания весов: база знаний — демонстрационные документы (контакты ответственных,
журнал работ, ППР зимних земляных работ, методика и ставки техники) плюс загруженные пользователем `.txt/.md/.csv/.docx/.xlsx`;
поиск — по основам слов с весами IDF; ответ собирается по шаблону типа вопроса. Для вопроса «текущий этап» можно выбрать
стройку — тогда ответ строится по её реальным данным. Ответ отдаётся потоком NDJSON
(`POST /api/assistant/chat`: `meta` → `delta`… → `done`), поэтому замена шаблонов на LLM и поиска на векторный
не требует правок интерфейса (`app/services/assistant.py`: `compose_answer`, `search`). ФИО и телефоны в демо-данных вымышлены.

## Дизайн

Два варианта, переключатель «Дизайн: Новый / Классический» — внизу боковой панели и в правом верхнем углу страницы входа.
Выбор запоминается в браузере. «Новый» — светлый редизайн; «Классический» — тёмная тема, как было до редизайна
(`frontend/src/views/classic/`: главная с крупными обложками, объект с героем-фотографией и шагами
«План → Снимки и камеры → Этап и отклонения → Таймлайн → Отчёт»). Карта строек и помощник работают в обоих вариантах.

Классический вариант:

Тёмная премиальная тема: фотография площадки — главный материал интерфейса, шампань-бронза `#CDB78F` только для акцента,
антиква Cormorant для заголовков и цифр, Onest для интерфейса. Шрифты подключаются с Google Fonts (`frontend/index.html`);
без интернета используются Georgia и системный гротеск. Токены — в `frontend/src/styles.css`.
HTML-отчёт в той же системе, но светлый — для печати.

## Детектор

| `DETECTOR`    | Что делает |
|---------------|------------|
| `ultralytics` | по умолчанию. `MODEL_WEIGHTS=yolov8s-worldv2.pt` — YOLO-World: открытый словарь, текстовые подсказки из методики, работает без дообучения. Любые `.pt` с классами из датасетов — метки переводятся в классы методики |
| `onnx`        | `MODEL_WEIGHTS=model.onnx`, `ONNX_CLASSES=excavator,dump_truck,...` — лёгкий CPU-вариант без torch |
| `mock`        | разметка из JSON (`MOCK_ANNOTATIONS_DIR`) — для тестов и демонстрации интерфейса |

Дообучение на датасетах из материалов хакатона (YOLO и Pascal VOC объединяются, метки приводятся к 14 классам методики):

```bash
python scripts/train_yolo.py --src datasets/roboflow datasets/kaggle --epochs 60 --model yolov8s.pt --export-onnx
MODEL_WEIGHTS=models/construction.pt docker compose up
```

## Что даёт бизнесу

- Простой техники переводится в рубли по ставкам из методики (нужна привязка снимков к камере — иначе простой неизмерим); дни отставания в деньги не переводятся сознательно
  (это завышало бы потери в сотни раз) — вместо этого показывается стоимость дня работы замеченной техники.
- Динамика готовности по записанным вердиктам: видно движение, а не одну точку.
- Ссылка на отчёт для заказчика: только чтение, ограниченный срок, вход не нужен.
- Выгрузка журнала отклонений в CSV для отчётности.

## Переменные окружения (backend)

`DATA_DIR` (БД, снимки), `SECRET_KEY` (пусто — генерируется и хранится в `DATA_DIR`), `DETECTOR`, `MODEL_WEIGHTS`,
`ONNX_CLASSES`, `DETECT_CONF` (0.25), `DETECT_IMGSZ` (1280), `DEVICE` (`cpu`/`0`),
`DETECT_TILES` (1; 2 — разрезание кадра для дальних планов), `MAX_UPLOAD_MB` (25), `CORS_ORIGINS`, `TOKEN_TTL_HOURS` (72),
`GEOCODER` (`auto` / `yandex` / `nominatim` / `off` — только встроенный справочник), `YANDEX_GEOCODER_KEY`, `NOMINATIM_URL`,
`GEOCODER_TIMEOUT` (4), `ASSISTANT_STREAM_DELAY` (0.025 — пауза между фрагментами ответа помощника, с).

## Тесты

```bash
cd backend && python -m unittest discover -s tests -t .
cd frontend && npm test          # node:test для lib и потокового клиента помощника + статическая проверка всех .vue
cd backend && SAMPLE_PHOTOS=/путь/к/снимкам python scripts/role_check.py   # прогон по ролям
```

`scripts/role_check.py` — разведочный прогон от лица руководителя, инженера, жюри, интегратора и злоумышленника:
печатает тайминги, число SQL-запросов и реакцию на некорректные данные. Им найдены и закрыты: показ готовности
без единого снимка, осиротевшие файлы после удаления объекта, SSRF в адресе камеры, N+1 в галерее (51 запрос → 4).

- Backend, 60 тестов. Справочник (377 позиций), методика, план, определение этапа, активность техники, вердикт
  (пример из ТЗ: экскаватор есть, самосвалов нет), таймлайн. Сквозной сценарий из 10 шагов на реальных снимках.
  Камеры-метки и серия кадров одной камеры, изоляция пользователей. Геокодирование без сети и ручная точка на карте,
  помощник: типы вопросов, поиск по загруженным документам, изоляция документов, формат потока.
  Этап по снимку с учётом количества техники, загрузка на этап, план ↔ факт, таблицы «тип ↔ этап ↔ техника»,
  расчёты техники и актуальность METHODOLOGY.md.
  Подготовка датасета для дообучения, декодер выхода YOLOv8, связка HTTP-роутов.
- Frontend: тесты lib (сводка стройки, карточка карты с экранированием, Markdown ответов), потоковый клиент помощника
  против настоящего HTTP-сервера с разрезанными чанками, и статический анализатор SFC. Анализатор проверяет синтаксис скриптов и выражений шаблона,
  баланс тегов, необъявленные идентификаторы, импорты, props и события компонентов.
